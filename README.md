# Portfolio website

A static portfolio site (Astro, plain HTML/CSS, no client framework, no analytics, no external fonts or scripts). Client-side JavaScript is vanilla TypeScript bundled by Astro, with no third-party code, and is used only by the CPU lab (`src/scripts/cpu-lab.ts` and `src/scripts/front-panel.ts`), the home-page pipeline teaser, the projects filter tabs and the research library (`src/scripts/research-lib.ts`: topic graph, catalog filter, keyword search); every page still reads correctly without it. It presents a few engineering projects together with their caveats, and a page on how results are verified.

## Run locally

```sh
npm ci
npm run dev                      # dev server
npm run build && npm run check   # production build + all checks
```

The checks need `python3` with `pillow` and `pyyaml`.

## Layout

- `src/content/pages/` and `src/content/projects/`: Markdown content (Astro content collections). Frontmatter: `title`, `summary`, `status`, `order`, `tags`, `repo`, `claims`; projects may set `visual` (`queue`, `pipeline`, `specimen`, `cpu`) and `area` (projects filter tab), and the verification page uses `cases` to build its audit cards.
- `content/claims.yaml`: the claims ledger, the source of truth for every number on the site.
- `content/research-library.json`: public export of the research knowledge base, written by `python3 scripts/export_research_library.py` (needs the private knowledge base locally; the script keeps only allowlisted fields and exits on any local path or passage id). `content/research-topics.yaml` and `content/research-qa.yaml` hold the topic descriptions and Q&A cards; a card shows a "Draft" label until its `status` is `reviewed`.
- `src/components/`: `StatusPill`, `ProjectCard`, the four card visuals (`visuals/`) and the CPU lab and home-page teaser (`cpu/`). `visuals/glyphs.json` comes from `python3 scripts/gen_glyphs.py <dir of Noto .woff files>`; rerun only if the specimen changes.
- `src/diagrams/*.svg`: diagrams, generated by `python3 scripts/gen_diagrams.py` and inlined at build time via `<figure data-diagram="name">`.
- `public/img/`: charts, photo and screenshot (EXIF stripped).
- `scripts/`: the checks, the Markdown plugin (`rehype-site.mjs`: base-aware links, heading ids, numeric table columns, inline diagrams and charts, lesson callouts, verification audit cards), the build-time chart renderer (`chart.mjs`; rows may carry a `tone` colour), and `gen_diagrams.py` / `gen_glyphs.py`.

## Base path

The same source builds for either hosting layout, controlled by environment variables:

| Variable | Default | Meaning |
|---|---|---|
| `SITE_URL` | `https://b-clown-code.github.io` | canonical site URL |
| `BASE_PATH` | `/` | `/` for `b-clown-code.github.io`, or `/portfolio_website/` for a project page |

Write internal links in Markdown as absolute paths (`/projects/gpu-scheduler/`, `/verification/#bf16`); they are prefixed with the base at build time.

## Design

Warm charcoal and cream with three tonal surfaces (`--bg-canvas`, `--bg-card`, `--bg-inset`), Instrument Sans (variable; its width axis gives the condensed headlines) for prose and JetBrains Mono only for metrics, status, tags, captions and numerals. Extra hues (moss, teal, plum, clay, gold) are used for status and chart tones, always alongside words. Fonts are self-hosted in `public/fonts/` with their licences. The CPU lab's tape labels use Permanent Marker (Apache-2.0); the browser loads it only on that page. Chestnut bands (`--band*` tokens) stay dark in both colour schemes. Contrast checks and decisions are recorded in `RELEASE_REVIEW.md` §E, §F and §J.

## Claims ledger and checks

`content/claims.yaml` is the source of truth. Each page lists the claim ids it relies on in its `claims` frontmatter, and every number in the page text must appear in one of those claims.

- `npm run check:claims`: numbers on each page are backed by that page's claims (structural exceptions in `scripts/claims-allowlist.txt`).
- `npm run check:scrub`: `dist/` contains no private hostnames, paths, addresses or names, and no JPEG has EXIF.
- `npm run check:links`: internal links and anchors resolve; external links are on an allowlist.
- `npm run check:cpu` (local only; needs `iverilog`, `vvp`, `python3`): the CPU lab's model and assembler match the CPU's Verilog cycle for cycle; writes `content/cpu-rtl-check.json`. See `scripts/cpu-rtl/README.md`.
- `npm run check:panel`: tests for the CPU lab's front-panel (single-cycle switch mode) model, `src/lib/cpu/single.ts`. Part of `npm run check`.
- `npm run check:panel-rtl` (local only; needs `iverilog`, `vvp`, `unzip` and the owner's single-cycle project zip, which is not committed): the front-panel model matches the November 2024 single-cycle Verilog press for press; writes `content/cpu-panel-rtl-check.json`.

## Deployment

`.github/workflows/deploy.yml` builds, runs the checks and deploys with the official Pages actions. It runs on every push to `main` and can also be started by hand. Set the repo variable `BASE_PATH` if the site is not served from the root.
